## 一、五大方法映射总览

### 1.1 认证模块

| 方法 | 输入条件分解 | 覆盖用例 |
| --- | --- | --- |
| 等价类 | 凭据正确 / 用户名不存在 / 密码错误 / 必填字段为空或缺失 / 长度越界 | AUTH-001 ~ 009 |
| 边界值 | username 50 / 51；password 64 / 65 | AUTH-008、009（需改造） |
| 判定表 | 有头? × 以 `Bearer ` 开头? × 签名有效? × 未过期? → 放行 / 401缺失 / 401无效 / 401过期 | AUTH-010 ~ 014 |
| 场景法 | 登录 → 取 token → 访问受保护接口 | 缺失，新增 AUTH-018 |
| 错误推测 | 纯空格凭据、凭据前后空格、`Bearer ` 空 token、alg=none | 新增 AUTH-016、017，并入 012 参数化 |

源码依据：`LoginRequest` = `@NotBlank("用户名不能为空")` `@Size(max=50)` / `@NotBlank("密码不能为空")` `@Size(max=64)`；`AuthInterceptor` 三种 401 message 分支；`JwtService` HS256 本地验签。

**关键结论**：原设计把「凭据错误」与「必填字段为空/缺失」当成同一等价类（统一预期 401），实际后端 Bean Validation 先执行 → 后者返回 **400**。这是 4 条失败用例的根因，属用例设计错误，不是被测缺陷。

### 1.2 员工模块

| 方法 | 输入条件分解 | 覆盖用例 |
| --- | --- | --- |
| 等价类 | name/phone/department/position/hireDate/status 各自：有效 / 空 / 格式非法 / 枚举非法 | EMP-004~013、EDT-006 |
| 边界值 | name 1/50/51；department 1/50/51；phone 10/11/12；page 0/1；size 0/1/100/101 | EMP-015/016/018/019、LIST-007~009（缺正边界对照） |
| 判定表 | JSON 可解析? × 必填完整? × 格式合法? × status 合法? × phone 未删除唯一? → 200/400/409，含优先级 | EMP-021、新增 EMP-025/026 |
| 场景法 | 建部门→建员工→列表→详情→编辑→删除→手机号复用 | 缺失，新增 EMP-027 |
| 错误推测 | 空格（name 被 trim、phone/status 不被 trim）、LIKE 通配符 `%`、id 非数字、软删除数据复用 | 新增 EMP-023/024、LIST-014、DET-005/006、EDT-004/008 |

源码依据（校验优先级，决定组合用例的预期）：
Jackson 反序列化 → `@Valid`（`@NotBlank`/`@Size`/`@Pattern`/`@NotNull`）→ `validateStatus`（枚举）→ `existsByPhone(deleted=0)` → 落库（字段统一 `trim()`，`hireDate` 为 `LocalDate`）。
时间字段：`createdAt/updatedAt` 由服务端 `DateTimeFormatter("yyyy-MM-dd HH:mm:ss")` 生成，`create()` 返回 `getDetail(id)`（DB 回读）。

## 二、冗余审计与删除清单（7 条）

判定标准：**输入条件等价 且 断言点相同 → 冗余**（不因"接口不同"或"写法不同"而豁免）。

| # | 删除用例 | 冗余理由 | 覆盖去向 |
| --- | --- | --- | --- |
| 1 | TC-AUTH-006 缺少 username 字段 | `@NotBlank` 对 `""`、字段缺失(null)、纯空格三者行为完全一致（均 400 "用户名不能为空"），与 TC-AUTH-004 同一等价类 | 并入 TC-AUTH-004 参数化行 |
| 2 | TC-AUTH-007 缺少 password 字段 | 同上 | 并入 TC-AUTH-005 参数化行 |
| 3 | TC-EMP-007 phone 含字母 | `@Pattern(^1[3-9]\d{9}$)` 是单一校验点，位数不足/含字母/号段非法/超长属同一正则失败分支 | 并入 TC-EMP-006 参数化 4 行 |
| 4 | TC-EMP-017 phone 非 1 开头 | 同上 | 并入 TC-EMP-006 参数化 4 行 |
| 5 | TC-EMP-022 验证 createdAt 由服务端生成 | TC-EMP-001 的请求体本就不含 createdAt/updatedAt，且已断言两者存在 → 无独立输入条件、无独立断言点 | TC-EMP-001 |
| 6 | TC-DEL-005 删除后详情不可查 | 与 TC-DET-003（创建→删除→详情 404）输入序列与断言完全一致，仅归属模块不同 | TC-DET-003 |
| 7 | TC-DEL-006 删除后列表不可查 | 与 TC-LIST-012（创建→删除→列表不含）完全一致 | TC-LIST-012 |

保留但说明理由（避免误删）：

- TC-DEL-001 vs TC-DEL-003：001 验证删除契约（200 + data=null），003 验证幂等（二次 404），断言点不同。
- TC-LIST-012 vs TC-DL-004、TC-DN-002：分属员工列表 / 部门列表 / 部门字典三个接口的独立可见性契约。
- TC-DP-004 vs TC-DU-002：新增重名 vs 编辑重名，判定表的两条不同规则。
- TC-EMP-021（`{}` 多字段同时为空）：断言点是"多条错误以 `; ` 聚合"，单字段用例无法覆盖。
